Three rules every plugin follows

Least access

A plugin gets the smallest scope the platform offers, even when a broader one would be easier to build against.

Nothing stored twice

Your data stays where it already lives. No copies on your web server, and none on mine, because there is no server of mine.

Readable, not minified

Plain PHP on WordPress.org and on GitHub, so you can check what a plugin sends before you install it.

Approach

Most plugins ask for far more than they use

Install something that connects WordPress to a cloud service and you are usually asked to grant access to everything in the account. That is convenient to build and hard to justify. If the plugin is compromised, or the developer's app registration is, the blast radius is the whole account.

Narrower options almost always exist. An app-scoped folder, a read-only token, a single resource instead of a directory. They cost some flexibility and a lot more work, and they mean the plugin cannot reach anything you didn't hand it, even if it has a bug.

That is the whole product idea, and it is also why each plugin stays small. One plugin, one job, one permission. If you want a suite that does everything, I'm not building that.
